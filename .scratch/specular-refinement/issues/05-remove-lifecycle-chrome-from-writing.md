# Remove lifecycle chrome from the writing surface

Type: enhancement
Status: resolved

## Current behavior

The document header displays an effective lifecycle label and a manual active/resting/closed selector. Every block also displays its effective lifecycle label. These controls repeat state that is not useful while the author is actively writing.

## Desired behavior

Remove document and block lifecycle labels and the document lifecycle selector from the writing surface. Preserve lifecycle fields, automatic dormancy, reactivation on edit, persisted closed states, and the organizational filters that use them elsewhere.

The document should feel active through focus and writing behavior rather than through status text. Existing workspaces must continue to load regardless of their stored lifecycle values.

## Key interfaces

- Document header and block metadata row.
- Effective dormancy calculation.
- Library and Connections lifecycle presentation.
- Persistence and reactivation behavior.

## Acceptance criteria

- Active, resting, closed, and dormant labels are absent from the document header and block rows.
- No lifecycle selector is present in the writing document.
- Editing a dormant or resting document still reactivates its stored state as before.
- Library and Connections lifecycle filters remain functional.
- Existing active, resting, closed, and dormant workspaces load without migration loss.
- Removing the controls does not shift delete, dictation, linked-block, or starter actions into ambiguous positions.

## Out of scope

- Removing lifecycle metadata from persistence.
- Redesigning Library or Connections lifecycle filters.
- Adding task-management status workflows.

## Comments

## Answer

Removed lifecycle labels and controls from the document and block rows while preserving stored lifecycle state, dormancy behavior, reactivation, and Connections organization.
