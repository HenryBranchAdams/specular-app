# Ban em dashes in interlocutor output

Type: enhancement
Status: resolved

## Current behavior

The reflection model may use em dashes in mirrors and directions. The current output contract validates structure but not this style rule.

## Desired behavior

All newly generated Specular prose must avoid the em dash character. The instruction and server-side output boundary must enforce the rule rather than relying on prompt compliance alone. Enforcement may repair punctuation without changing the substance of a response.

The rule applies to mirrors, direction prompts, calibration replies, and generated titles. It does not modify canonical user writing, imported source titles, source excerpts, URLs, or previously stored content.

## Key interfaces

- Reflection and automatic-organization instructions.
- Structured model-output validation and repair.
- Stored margin annotations and generated titles.

## Acceptance criteria

- New model-authored mirrors, directions, calibration responses, and generated titles contain no U+2014 character.
- A provider response containing an em dash is repaired or rejected before it reaches visible product state.
- User-authored text containing an em dash remains byte-for-byte unchanged.
- Source metadata and quoted excerpts containing an em dash remain unchanged.
- Existing stored annotations are not rewritten by migration.
- Deterministic tests cover compliant output, violating output, user prose, and source prose.

## Out of scope

- Banning hyphens or en dashes.
- Rewriting historical data.
- Applying broader house-style edits to user writing.

## Comments

## Answer

Added model instructions plus deterministic server-boundary sanitization for reflections, directions, calibration replies, and generated titles. User-authored prose and source metadata remain untouched, with tests covering both sides of the boundary.
